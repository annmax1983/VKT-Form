01Overview

VKT Form is a browser extension that saves and fills web form data. By default, all data is stored locally in your browser using storage.local, and no data is uploaded to any server. Pro users can optionally turn on cross-device sync, which stores snapshots in their browser account's built-in sync service, operated by the browser vendor (Google for Chrome, Microsoft for Edge, Mozilla for Firefox). We do not operate a sync server, and we never receive your snapshots.

02Data Collection

VKT Form collects the following data only when you manually click the "Collect" button:

  • Form field names, values, and types (text, radio, checkbox, select, textarea, contenteditable)
  • The URL of the page where forms are collected — both a normalized URL and the raw URL
  • Structural hints used to match the same fields again later: label text, placeholder, nearby text, autocomplete attribute, and a DOM path / DOM order index
  • Whether each field was hidden from view at the moment of collection (framework-hidden inputs and inactive steps of multi-step forms are collected too)
  • Password fields (input[type=password]) are not collected by default; they are captured only if you turn on Settings → "Include password fields"

Important: The extension does NOT automatically collect any data. All scanning is user-initiated, and the scan runs only on the tab you are looking at.

By default, everything the extension stores lives in your browser's storage.local, under these keys:

Local data is never transmitted externally unless you turn on Pro cross-device sync. The export/import feature simply writes a JSON file to your own disk and reads one back — that file never leaves your machine unless you move it yourself.

04Cross-device Sync (Pro, Optional)

Cross-device sync is off by default. It requires an active Pro license and must be enabled by you in Settings → Cross-device sync. It uses storage.sync, the browser's own sync facility, which is operated by your browser vendor and associated with the browser account you are signed in to. We have no access to this data and do not receive a copy of it.

When sync is enabled, the following items are written to storage.sync:

  • Each snapshot's name, normalized URL, raw URL, timestamps, and field count, under a meta item named vkf_sync_<hash>_meta
  • The snapshot's field entries, split into chunks named vkf_sync_<hash>_<revision>_<index>. This includes every captured field value, including sensitive fields, in plain text.
  • A list of deletion markers under vkf_sync_tombstones, so deletions propagate to your other devices

The browser enforces a quota of 8 KB per item and about 100 KB in total. Large snapshots are split into chunks to fit. If a snapshot does not fit, it remains saved locally and the side panel reports that it could not be synced.

Data in storage.sync is stored and transmitted by your browser vendor under its own terms and privacy policy. It may appear on other devices signed in to the same browser account, subject to the vendor's sync behavior and latency.

Turning sync off stops future syncing but does not erase copies already stored in your browser account. To remove those, delete the snapshots while sync is on, or manage/clear the extension's synced data through your browser account settings.

05Sensitive Fields

By default VKT Form skips password fields when you click "Collect", so their values are not stored unless you turn on Settings → "Include password fields". Nothing else is filtered: if a payment card number, a one-time code (OTP) or another credential sits in an ordinary fillable field when you click "Collect", its value is captured and stored — locally, in your browser, in plain text (it is not encrypted).

If you enable Pro cross-device sync, these values are also uploaded to your browser account's sync service as part of the snapshot, exactly like any other field. They are never sent to our servers.

Please be aware of this when using the extension on pages containing credentials, and prefer deleting the snapshot once you no longer need it. VKT Form is a form-snapshot tool, not a password manager.

The extension uses chrome.scripting and the chrome.debugger API to interact with form fields on the page you are acting on. Form data is never transmitted to our servers. The only requests the extension makes are license-key validation (see below), and — only if you enable cross-device sync — the browser's own account sync. The debugger API is used only on Chrome / Edge; Firefox has no extension debugger API, so that filling strategy is not available there.

07Third-Party Services

License key validation communicates with api.annmax1983.com to verify Pro status. The request contains the license key, a randomly generated install identifier, the plugin ID, and basic browser metadata (browser name and major version, interface language, time zone and user-agent string). No form data or browsing history is transmitted. Our license server records the IP address of these requests solely for rate limiting and abuse prevention — never for profiling, advertising, or sharing with third parties.

When cross-device sync is enabled, snapshot data is handled by the browser vendor's account sync service (Google for Chrome, Microsoft for Edge, Mozilla for Firefox). That processing is governed by the vendor's terms and privacy policy, not ours. We do not receive, store, or have access to that data.

08Data Retention & Deletion

You delete snapshots from the extension's side panel — each snapshot row has a delete button, and it asks for confirmation first. (There is no popup UI and no "delete everything" button; snapshots are removed one at a time.)

If sync is enabled, deleting a snapshot also removes it from storage.sync and records a deletion marker so your other devices remove it too. Deletion markers are pruned after about 180 days. If sync is off, only the local copy is deleted; copies already in your browser account are not affected.

To erase local data at once, uninstall the extension — the browser removes its local storage with it. Uninstalling does not guarantee that copies previously synced to your browser account are removed, because that storage is controlled by the browser vendor; delete snapshots while sync is on, or clear the extension's synced data in your browser account settings. No data is retained on our servers, because none was ever sent to them.
